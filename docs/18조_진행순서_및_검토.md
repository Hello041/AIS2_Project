## 검토 결과

구현계획서를 기획서·저장소와 대조해 찾은 문제다. 문서에 없는 사항은 '확인 필요'로 표시했다.

### 꼭 고칠 것

1. **HMAC 서명 검증이 실패할 수 있다 (§12.6).** 앱이 결과를 JSON으로 파싱했다가 `/records`에 다시 보내면 JS가 `1.0`을 `1`로 바꿔, 서명한 바이트와 달라진다. 확인 필요: 서명 대상을 문자열 그대로 전달할지, 실수를 고정 자릿수로 맞출지.
2. **문서의 링크·경로가 틀렸다.**
    - `../AI_이미지_판별_서비스_기획서.md` → `AI_이미지_판별_서비스_기획서.md` (같은 폴더)
    - `../BIN0002.png` → `images/BIN0002.png`
    - §4 구조도의 `docs/MVP_구현계획서.md` → 실제 파일 이름
3. **데모 네트워크 준비가 빠져 있다 (§3).** ngrok 무료 버전은 `ngrok-skip-browser-warning` 헤더가 없으면 JSON 대신 경고 HTML을 돌려준다. 같은 Wi-Fi에서는 서버를 `0.0.0.0`으로 실행하고 Windows 방화벽 포트를 열어야 한다.
4. **413은 자동으로 나오지 않는다 (§5.4).** FastAPI/uvicorn에는 기본 업로드 크기 제한이 없어 10MB 검사를 직접 구현해야 한다.

### 설계상 주의

5. **§5.3 규칙 3은 중복이다.** 세 구간이 모두 다르면 `strong`과 `weak`가 함께 있어 규칙 1에서 이미 걸러진다. 동작은 같으므로 단위 테스트 목록만 정리하면 된다.
6. **스태킹에서 데이터가 섞일 위험이 있다.** Platt·LR·τ·`t_high`는 각 fold의 학습 부분에서만 맞춰야 한다. 실제 사진이 약 100장이라 FPR 5%는 5장 차이다.
7. **화면이 모순돼 보일 수 있다.** 모델별 막대는 원점수 경계값으로, 종합 배지는 스태킹으로 정해 "막대 3개 모두 약함, 종합은 어려움"이 나올 수 있다. 시연 설명을 준비해야 한다.
8. **기획서와 다른 점이 있다.**
    - 전이학습: 기획서는 확정 기능(전이학습 → 융합 순서), 계획서는 조건부(우선순위 8)
    - 판정 안정성: 기획서는 원점수 막대, 계획서는 구간만 표시
    - 확인 필요: 의도한 변경인지. 의도했다면 보고서에 사유를 남겨야 한다.
9. **`shared/`와 HF Spaces 빌드.** HF Spaces는 별도 저장소에서 Docker를 빌드한다. 확인 필요: `inference/` 밖의 `shared/`를 빌드에 어떻게 포함할지.
10. **사용량 제한 우회.** 저장할 때만 사용량을 세면, 저장을 건너뛰는 클라이언트는 IP 제한(분당 20회)만 받아 하루 최대 약 28,800회까지 가능하다. 문서에 수치를 적어 두면 질문에 대응하기 좋다.

### 작은 것

- requirements에 버전이 고정되어 있지 않다. AIDE 공식 코드가 특정 버전(`timm` 등)을 요구할 수 있다.
- UnivFD 공식 코드는 OpenAI `clip` 패키지를 쓴다. open_clip으로 바꾸면 가중치와 전처리가 같은지 확인해야 한다.
- 확인 필요: `banding` 단위 테스트를 둘 위치가 §4 구조도에 없다.
- 확인 필요: `usage_daily.day`의 기준 시간대.
- iOS에서 사진을 고를 때 HEIC가 넘어오거나 `fileSize`/`mimeType`이 비어 있을 수 있다. 앱의 형식 검사에서 대비해야 한다.

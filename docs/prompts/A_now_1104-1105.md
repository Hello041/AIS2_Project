### A1. manifest.csv 형식 확정 (공통)

```
ml/data/manifest.csv의 헤더를 정하자. 브랜치: feat/manifest

근거: 계획서 §4(원본 ID, 정답, 버전, 출처·라이선스), §5.3(GroupKFold는 원본 ID 기준), §8(생성기·출처 기록), §12.4(4개 버전으로 800장까지 확장).

   image_id, source_id, label(real|ai), version(original|jpeg70|resize50|screenshot),
   file_path(ml/data/ 기준 상대경로), generator(실제 사진은 camera 또는 빈칸),
   source_url, license, collected_by, notes
2. 내가 확정하면 manifest.csv에 헤더만 쓰고, ml/data/README.md에 각 열의 의미·허용값·명명 규칙

3. ml/data/validate_manifest.py: 헤더 일치, label·version 허용값, image_id 중복, 같은 source_id 안에서
   label이 섞이지 않는지, file_path 존재 여부를 검사하는 스크립트. 문제 행을 출력하고 종료 코드로 알려줘.
4. .gitignore에서 ml/data/ 아래 이미지가 제외되고 manifest.csv와 README.md는 포함되는지 확인.
```

### A2. 모델 코드·가중치 확보와 라이선스 (김정효)

```
UnivFD, NPR, AIDE의 공식 코드와 가중치를 확보하고 라이선스를 정리하자. 브랜치: feat/model-sources

1. 각 모델의 공식 저장소를 웹에서 찾아 다음을 표로 정리해줘:
   저장소 URL, 코드 라이선스, 가중치 다운로드 위치, 가중치 라이선스(명시 안 됐으면 '명시 없음'),
   가중치 학습 데이터(UnivFD=ProGAN 등), 요구 패키지와 버전(특히 AIDE의 timm, UnivFD의 clip).
2. 가중치를 inference/weights/에 내려받는 스크립트 inference/scripts/download_weights.py를 작성해줘.
   이미 있으면 건너뛰고, 받은 뒤 파일 크기와 sha256을 출력.
   (네트워크가 막혀 있으면 내가 직접 받을 수 있게 URL과 저장 경로 목록만 줘.)
3. inference/README.md 작성: 가중치 받는 법, 라이선스 표, 주의사항
   (UnivFD는 OpenAI clip 사용, open_clip 교체 시 검증 필요 등).
4. 각 모델이 요구하는 패키지 버전을 requirements.txt에 고정 버전으로 반영하되,
   세 모델 간 충돌이 있으면 바꾸기 전에 알려줘.

가중치 파일은 커밋하지 마.
```

### A3. 메모리·추론 시간 측정 (김정효)

```
ml/measure.py를 작성하고 실행해서 계획서 §7을 채우자. 브랜치: feat/measure

1. 각 모델을 따로 로드하고 측정:
   - 로드 전후 RSS 증가량(psutil), 로드 시간
   - 이미지 1장 추론 시간: 워밍업 1회 후 5회 평균·최대 (torch.inference_mode, 배치 1, CPU)
2. 세 모델을 함께 로드했을 때의 총 RSS와 순차 추론 총 시간도 측정.
3. 입력 이미지는 인자로 받고, 없으면 임의의 1024x1024 이미지를 만들어 써.
4. 아직 detectors/가 없으니 이 스크립트 안에서는 공식 코드의 로드·추론 함수를 직접 호출해도 된다.
   단 UnivFD는 이미지 인코더만 로드해.
5. 결과를 표로 출력하고, 계획서 §7 표 아래에 '실측값 (측정일, CPU 모델명, torch 버전)' 표를 추가해줘.
6. 판단 보고: 60초 기준과 16GB RAM 기준을 넘는 모델이 있는지, 특히 AIDE를 그대로 쓸 수 있는지.
   넘으면 대안(입력 크기 축소, fp16/bf16 가능 여부, 대체 모델 후보)을 제시해줘.
```
